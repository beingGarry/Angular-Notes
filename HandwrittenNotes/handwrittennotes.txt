Page 45 — Promises in Angular

Promises In angular.

A promise in angular is a JS object which produces value after an async operation is executed successfully.

If the operation does not execute successfully, then it generate an error.

A promise in angular is a class-based object, it is created using new keyword and its constructor function.

It is defined by passing a callback function also known as the executor function as an argument to the promise constructor.

The executor function usually takes two argument (Resolve, and reject).

Const myPromis = new Promise((resolve, reject) => {

 setTimeout(() => {

   resolve("this is a promise");

 }, 300)
})
myPromis.then((value) => {
 console.log(value);
})

// expected output : "this is promise"

Page 46 — Promise States / then()

Promise object have a then() and catch() methods which handles fulfilled result and error if occurs.

They receive the outcome of async operation as data or error from the resolve and reject handlers in the promise constructor.

Promise has three state

Pending :

This is an initial state, which is neither fulfilled nor rejected.

fulfilled :

operation is completed successfully

Rejected :

This means operation has failed.

A promise in Angular is said to be settled if it is either fulfilled or rejected.
It can not be in pending state.
.then()
Runs immediately after the promise has been fulfilled or rejected or after resolved is called.
then takes the callback function which receives the result when resolve is called. i.e then(function).
The callback function then takes result as an argument
Result is the value that we passed on to resolve as an argument when calling it. i.e Resolve(value)
Page 47 — catch() / finally()

.Catch
catch run immediately after reject (error) executed by the executer. That is after the promise has been rejected.
.Finally
The finally handler runs after the promise is settled. settled means that the promise is either fulfilled or rejected.
whether the promise was fulfilled or rejected.
finally is always going to run.
It does not process a promise but rather finalizes everything after the previous operation have been completed.
Promise = new Promise((resolve, reject) => {

 setTimeout(() => {

   let count = 5

   if(count === 5) {
     resolve("done")
   } else {
     reject(new Error("oops something went wrong"))
   }

 },2000)

})
Promise.then((result) => {
 console.log(result)
})
.catch((error) => {
 console.log(error)
})
.finally(() => {
 console.log("everything is finalized")
})

Page 49 — Subjects in Angular

Subjects in Angular:

Subjects are a special type of observables in angular’s RxJS library that allows you to multicast values to multiple observers.

Unlike regular observables, subjects are both an observable and an observer, meaning they can emit values and also be subscribed to.

Subject :

A basic subject can emit values to multiple subscribers.

Emit values to all subscribers
Does not hold onto values, new subscriber will not receive previous values.

subject.next(3);

Page 70 — Spread vs Rest Operator

The spread operator in javascript is a syntax introduced in ECMAScript 6 that allows you to spread the elements of an iterable such as arrays, strings or object, into another iterable or function call.
It is denoted by (...) followed by expression or an iterable.
It can be used to concatenate arrays, create shallow copies of arrays, convert strings into array of characters, merge or clone object and dynamically pass values into function.
Spread operators are always on the right side of expression.
If we use it on left side of expression then it will work as rest parameter.
Rest element must be the last element.

e.g

slice()
The slice() function creates a duplicates of a specified section of an array in a new array.
The original array is not modified.
The term slice literally means to cut something into pieces. It is used to cut out elements from an array. It does not affect original array.

Page 87 — Synchronous vs Asynchronous Programming

Asynchronous and Synchronous
Synchronous Programming
In synchronous programming, tasks are executed one after another in sequence.
Each task must complete before the next one can begin.
The program waits for a task to finish before moving on to the next one.
Makes execution predictable but potentially slower, especially if a task involves waiting (like network requests).
Asynchronous Programming
Asynchronous programming allows multiple tasks to run concurrently without waiting for each to complete.
It improves efficiency by enabling tasks like network requests.
The program doesn't wait for an asynchronous task to complete before continuing with the next task.

let
Declare block-scoped variables.
Prevents issues like variable hoisting seen with var.
Used when you need to reassign values.
const
Declare block-scoped constants.
Cannot be reassigned after initialization.
Useful for values that should not change.
var
Variables declared with var can be redeclared and reassigned without issue.
Variables declared with var have global scope if declared outside a function.
Variables declared with var have function scope if declared inside a function.
var is hoisted to the top of its execution context and initialized as undefined.
let
Variables declared with let cannot be redeclared but can be reassigned.
It has block scope if declared inside a block.
It has function scope if declared inside a function.
Page 90 — let vs const

let
Variables declared with let have global scope for the same file (not all files) if declared outside a function and block.
If let variable is declared inside a block, it cannot be accessed outside the block.
const
The const keyword variable must be declared and assigned together, otherwise it throws an error.
Variables declared with const cannot be redeclared nor reassigned.
It has block scope if declared inside a block.
It has function scope if declared inside a function.
It has global scope for the same file if declared outside a function.

2) Arrow Function
Arrow function allows a shorter syntax for writing function expressions.
You don't need the function keyword, return keyword and curly brackets (for simple expressions).
ES5
var x = function(x, y) {
  return x * y;
}
ES6
var x = (x, y) => x * y;
They do not have their own this.
They are not suitable for defining object methods.
They are not hoisted. They must be defined before use.
3) Object Destructuring
When destructuring objects, you must use the same names as the corresponding object keys (names).
The order of the keys does not matter.

Page 93 — switchMap / concatMap / mergeMap / exhaustMap

switchMap
When a bunch of values are emitted quickly, switchMap only cares about the latest one and ignores the rest.
It does not wait for the previous call to complete before making a new one.
concatMap
Processes observables sequentially.
Ensures the next observable starts only after the previous one completes.
Creates a queue of requests and handles them one after another.
Waits for the previous call to finish before making the next one.
mergeMap
Unlike concatMap, mergeMap does not wait for the previous call to finish.
Emits all requests as they come in, processing them at the same time.
Response order may not match request order.
exhaustMap
Processes the first request and ignores all other requests until the first one is completed.
Page 94 — Event Loop in JavaScript

Event Loop in JS
The event loop in JavaScript is a mechanism that allows the language to handle multiple operations, like user interaction or server responses, without blocking the main thread.
How it is executed
1) Call Stack
Where your code gets executed, one function at a time.
2) Web APIs
Handle asynchronous tasks like timers or network requests.
3) Callback Queue / Task Queue
Holds asynchronous tasks that are ready to be processed.
4) Event Loop
Constantly checks if the call stack is empty.
If it is empty, it takes tasks from the callback queue/task queue and adds them to the call stack for execution.
