

Old Angular Bootstrapping — NgModule

The startup flow is:

Browser
   ↓
index.html
   ↓
main.ts
   ↓
platformBrowserDynamic()
   ↓
AppModule
   ↓
bootstrap: [AppComponent]
   ↓
AppComponent
   ↓
<app-root>

1. index.html

The browser loads:

<!doctype html>
<html lang="en">

<head>
  <meta charset="utf-8">
  <title>MyApp</title>
  <base href="/">
</head>

<body>

  <app-root></app-root>

</body>

</html>

Again:

<app-root></app-root>

is where Angular's root component will eventually be rendered.

2. main.ts

This is where old Angular bootstrapping begins.

import { platformBrowserDynamic } from '@angular/platform-browser-dynamic';

import { AppModule } from './app/app.module';

platformBrowserDynamic()
  .bootstrapModule(AppModule)
  .catch(err => console.error(err));

The important part is:

platformBrowserDynamic()
  .bootstrapModule(AppModule);

This means:

"Start Angular and bootstrap the AppModule."

3. What is platformBrowserDynamic()?
platformBrowserDynamic()

creates the Angular platform for running an application in the browser.

Then:

.bootstrapModule(AppModule)

tells Angular:

"Use AppModule as the root module of my application."

So:

platformBrowserDynamic()
             ↓
        bootstrapModule()
             ↓
          AppModule

4. app.module.ts

Now Angular loads:

import { NgModule } from '@angular/core';
import { BrowserModule } from '@angular/platform-browser';

import { AppComponent } from './app.component';

@NgModule({

  declarations: [
    AppComponent
  ],

  imports: [
    BrowserModule
  ],

  providers: [],

  bootstrap: [
    AppComponent
  ]

})
export class AppModule {}

There are four important sections here.

declarations
declarations: [
  AppComponent
]

This tells Angular:

These components/directives/pipes belong to this module.

For example:

declarations: [
  AppComponent,
  HeaderComponent,
  UserComponent
]
imports
imports: [
  BrowserModule
]

This imports other Angular modules that this module needs.

For example, older applications might have:

imports: [
  BrowserModule,
  FormsModule,
  HttpClientModule,
  RouterModule
]
providers
providers: []

Used to register services/dependencies.

For example:

providers: [
  UserService
]

Although modern Angular often uses:

@Injectable({
  providedIn: 'root'
})

instead.

5. Most Important — bootstrap
bootstrap: [
  AppComponent
]

This tells Angular:

"After starting AppModule, use AppComponent as the root component."

So the chain is:

main.ts
   ↓
bootstrapModule(AppModule)
   ↓
AppModule
   ↓
bootstrap: [AppComponent]
   ↓
AppComponent
6. How Does <app-root> Connect?

AppComponent:

@Component({
  selector: 'app-root',
  template: `
    <h1>Hello Angular</h1>
  `
})
export class AppComponent {}

Notice:

selector: 'app-root'

And index.html has:

<app-root></app-root>

Angular connects them:

AppComponent
    ↓
selector: app-root
    ↓
<app-root>
    ↓
<h1>Hello Angular</h1>

9. Old vs Modern Bootstrapping

This is very important for interviews.

Old Angular                         	Modern Angular
AppModule                             	Standalone components
@NgModule	                            @Component({ standalone: true })
bootstrapModule()	                    bootstrapApplication()
platformBrowserDynamic()	            bootstrapApplication()
bootstrap: [AppComponent]	            bootstrapApplication(AppComponent)
Module-based DI/config	                app.config.ts / providers


Old
platformBrowserDynamic()
  .bootstrapModule(AppModule);

Then:

@NgModule({
  bootstrap: [AppComponent]
})
export class AppModule {}
Modern
bootstrapApplication(
  AppComponent,
  appConfig
);

No AppModule is required.

⭐ Interview Answer

If they ask:

"Explain bootstrapping in the old Angular architecture."

Say:

"In the NgModule-based Angular architecture, the application starts from main.ts. We use platformBrowserDynamic().bootstrapModule(AppModule) to bootstrap the root AppModule. Inside AppModule, we specify AppComponent in the bootstrap array, which tells Angular to use AppComponent as the root component. Angular then matches its app-root selector with the <app-root> element in index.html and renders the application."

The one line you absolutely need to remember:

platformBrowserDynamic()
  .bootstrapModule(AppModule);

And then inside AppModule:

bootstrap: [AppComponent]

That's the old Angular bootstrapping chain.













# *******************************************************************************************************************************************
Let's focus only on modern Angular (standalone) and understand what happens code-wise from browser startup → AppComponent → Angular application.

- Assume a modern Angular project created with:

ng new my-app
1. First: Browser loads index.html

Your src/index.html looks roughly like:

<!doctype html>
<html lang="en">

<head>
  <meta charset="utf-8">
  <title>MyApp</title>
  <base href="/">
  <meta name="viewport" content="width=device-width, initial-scale=1">
</head>

<body>

  <app-root></app-root>

</body>

</html>

The browser loads this file first.

At this point:

<app-root></app-root>

is just an HTML element.

Angular has not started yet.

2. Browser loads main.ts

Angular's build process knows that main.ts is the application entry point.

Modern Angular main.ts:

import { bootstrapApplication } from '@angular/platform-browser';

import { AppComponent } from './app/app.component';

bootstrapApplication(AppComponent)
  .catch(err => console.error(err));

The important line is:

bootstrapApplication(AppComponent);

This is where bootstrapping starts.

3. What does bootstrapApplication() mean?

Think of:

bootstrapApplication(AppComponent);

as saying:

"Angular, start my application and use AppComponent as the root component."

So the flow becomes:

index.html
     ↓
main.ts
     ↓
bootstrapApplication()
     ↓
AppComponent
4. Where does <app-root> come from?

Your AppComponent has a selector.

For example:

@Component({
  selector: 'app-root',
  standalone: true,
  template: `
    <h1>Hello Angular</h1>
  `
})
export class AppComponent {}

The important part is:

selector: 'app-root'

This matches:

<app-root></app-root>

in index.html.

So Angular essentially connects:

AppComponent
     ↓
selector: 'app-root'
     ↓
<app-root></app-root>

and renders the component's template there.

5. Complete Example
index.html
<body>

  <app-root></app-root>

</body>
main.ts
import { bootstrapApplication } from '@angular/platform-browser';

import { AppComponent } from './app/app.component';

bootstrapApplication(AppComponent)
  .catch(err => console.error(err));
app.component.ts
import { Component } from '@angular/core';

@Component({
  selector: 'app-root',
  standalone: true,
  template: `
    <h1>Hello Angular</h1>
  `
})
export class AppComponent {}

The startup flow:

Browser
   ↓
index.html
   ↓
<app-root></app-root>
   ↓
main.ts
   ↓
bootstrapApplication(AppComponent)
   ↓
Angular creates AppComponent
   ↓
selector = app-root
   ↓
Angular finds <app-root>
   ↓
Renders AppComponent template
   ↓
<h1>Hello Angular</h1>
6. But What About app.config.ts?

This is another important part of modern Angular bootstrapping.

You will often see:

bootstrapApplication(AppComponent, appConfig)
main.ts
import { bootstrapApplication } from '@angular/platform-browser';

import { AppComponent } from './app/app.component';
import { appConfig } from './app/app.config';

bootstrapApplication(AppComponent, appConfig)
  .catch(err => console.error(err));

And:

app.config.ts
import { ApplicationConfig } from '@angular/core';

export const appConfig: ApplicationConfig = {
  providers: []
};

The second argument:

appConfig

contains application-level configuration/providers.

7. Example: Router During Bootstrapping

Suppose you have:

import { ApplicationConfig } from '@angular/core';

import { provideRouter } from '@angular/router';

import { routes } from './app.routes';

export const appConfig: ApplicationConfig = {

  providers: [
    provideRouter(routes)
  ]

};

Then:

bootstrapApplication(AppComponent, appConfig);

means:

Start Angular
     ↓
Create application
     ↓
Register providers
     ↓
Register Router
     ↓
Create AppComponent
     ↓
Application starts
8. Example: HttpClient

You can also provide HttpClient during bootstrap.

app.config.ts
import { ApplicationConfig } from '@angular/core';

import {
  provideHttpClient
} from '@angular/common/http';

export const appConfig: ApplicationConfig = {

  providers: [
    provideHttpClient()
  ]

};

Then:

bootstrapApplication(AppComponent, appConfig);

Now services can inject:

constructor(private http: HttpClient) {}
9. What Actually Happens Inside Angular?

At a high level:

bootstrapApplication(AppComponent, appConfig);

Angular:

Step 1 — Creates the Angular application
Angular Application
Step 2 — Creates the Dependency Injection environment

It registers providers from:

appConfig

For example:

providers: [
  provideRouter(routes),
  provideHttpClient()
]
Step 3 — Creates the root component
AppComponent
Step 4 — Angular looks for the root component's host element

The selector is:

selector: 'app-root'

Angular finds:

<app-root></app-root>
Step 5 — Angular renders the component
<h1>Hello Angular</h1>
10. Where Does main.ts Come From?

This is also worth knowing.

In angular.json, the build configuration has an entry point such as:

{
  "build": {
    "options": {
      "browser": "src/main.ts"
    }
  }
}

Depending on the Angular version/project configuration, you may see browser, or older projects may use main.

The important concept is:

Angular CLI
     ↓
knows application's entry point
     ↓
main.ts

12. One Important Correction

Don't say:

"main.ts directly calls AppComponent."

More accurately:

"main.ts calls bootstrapApplication() and passes AppComponent as the root component. Angular uses that component to create the root of the application."

⭐ Interview Answer

If the interviewer asks:

"What is bootstrapping in modern Angular?"

Say:

"In modern standalone Angular, bootstrapping is the process of starting the Angular application using bootstrapApplication(). The application entry point is usually main.ts, where we call bootstrapApplication(AppComponent, appConfig). AppComponent becomes the root component, while appConfig provides application-level configuration such as Router, HttpClient, and other providers. Angular creates the application and root component and renders it into the <app-root> element defined in index.html."

The key code to remember is simply:

bootstrapApplication(AppComponent, appConfig);

AppComponent = what to start
appConfig = how the application is configured
index.html = where the root component is rendered
