* In Angular, signals represent a new way to manage and react to changes in data, similar to how RxJS Observables or Angular’s change detection works. 

- Signals allow Angular applications to 'track data changes' reactively and automatically update parts of the UI whenever the data changes.


Simple Explanation of Signals:

1. Signals Hold Data:

Whenever you change the data inside the signal, it automatically notifies anything that depends on it, like your components or the UI.

2. Automatic UI Updates:

If your UI is showing a value stored in a signal, and the signal changes, the UI will automatically update to reflect the new value, without needing manual updates or complex change detection.

* How Signals Work:

- Reactive by Nature: Signals work reactively, meaning that if a signal's value changes, any part of your app that depends on it will automatically respond to the change.

- Simpler Than Observables: Unlike RxJS observables, which require subscribing and managing streams of data, signals are simpler to use for basic reactivity. 

You don’t need to subscribe to them, they just automatically update when their data changes.

Key Operations with Signals:

Creating a Signal: You can create a signal with an initial value.


const count = signal(0);
Here, count is a signal that starts with the value 0.

Reading a Signal's Value: To access a signal's current value, just call it:

typescript
Copy code
console.log(count());  // Prints: 0
Updating a Signal's Value: You can update the value inside a signal like this:

typescript
Copy code
count.set(5);  // Changes count to 5
console.log(count());  // Prints: 5

Reactivity: If your UI displays the value of count, changing count will automatically update the UI.

Simple Example in an Angular Component:
typescript
Copy code
import { Component, signal } from '@angular/core';

@Component({
  selector: 'app-counter',
  template: `
    <h1>{{ count() }}</h1>
    <button (click)="increment()">Increment</button>
  `
})
export class CounterComponent {
  count = signal(0);  // Create a signal with an initial value of 0

  increment() {
    this.count.set(this.count() + 1);  // Update the signal's value
  }
}
In this example:

count() shows the current value of the count signal.
When the button is clicked, the increment() function updates the signal. The UI automatically updates to show the new count without needing manual change detection.

- Benefits of Signals:

- Simplicity: Easier to use than RxJS for simpler scenarios.

- Automatic Reactivity: No need to manually manage subscriptions or updates.

- Efficient: Signals provide optimized updates to the DOM, making your app more efficient.

Use Case:

* Signals are especially useful when you want to build reactive UIs that respond to data changes in a simple and efficient way, without needing the complexity of RxJS or manual change detection.

* In short, signals provide an easy and automatic way to manage reactive data and keep your UI updated in Angular.


In Angular Signals, everything revolves around:

Reading → signal()
Writing → set() / update()
Deriving → computed()
Reacting → effect()

Angular internally tracks dependencies automatically (no manual subscribe/unsubscribe like RxJS).

- TYPES OF SIGNALS (Deep Explanation)

1. WritableSignal (Most Important)

This is what you create using signal().

count = signal(0);

- What it does:Holds state, Can be changed, Notifies all dependents

✔ Methods available:
set()
update()
mutate() (for objects/arrays)
asReadonly()

🔹 Methods Explained

1. set(value)

Replaces value completely

count.set(10);

👉 No dependency on previous value

2. update(fn)

Updates using previous value

count.update(v => v + 1);

👉 Best for counters, toggles, accumulations

3. mutate(fn)

Used for reference types (array/object)

users = signal([{ name: 'A' }]);

users.mutate(arr => {
  arr.push({ name: 'B' });
});

👉 Why needed?
Because Angular tracks reference change — mutate tells Angular:

“I changed internal data, re-render”

4. asReadonly()
readonlyCount = count.asReadonly();

👉 Prevents external modification




==========================================================================
2. ComputedSignal (Derived State)


total = computed(() => this.price() * this.quantity());

- What it does: Depends on other signals, Auto recalculates, Cached (only recalculates when dependency changes)

🔹 Important Behavior
Lazy execution → runs only when accessed
Memoized → avoids unnecessary recalculation
 Not allowed: total.set(100);

👉 "Computed is read-only"

✔ Advanced Example
price = signal(100);
quantity = signal(2);

total = computed(() => {
  console.log('Recalculating...');
  return this.price() * this.quantity();
});

👉 console.log runs ONLY when dependencies change
===================================================================
3. Effect (Side Effects Engine)
effect(() => {
  console.log(this.count());
});

✔ What it does:
Runs automatically when dependencies change
Tracks signals inside it

🔹 Behavior

Runs once initially
Re-runs when any used signal changes
✔ Cleanup support

effect((onCleanup) => {
  const id = setInterval(() => {
    console.log(this.count());
  }, 1000);

  onCleanup(() => clearInterval(id));
});

👉 Important for memory leaks

❗ Rule:

👉 Use effect ONLY for side effects

✔ Logging
✔ API call trigger
✔ DOM interaction

❌ Don’t use for derived values → use computed



👉
“Angular Signals are reactive primitives consisting of writable signals, computed signals, and effects.
 Writable signals manage state using methods like set, update, and mutate. 
 Computed signals derive state reactively and are memoized. 
 Effects handle side effects and automatically re-run when dependencies change.”
