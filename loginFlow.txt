Authentication Flow in Angular
1. Login API

When user enters username/password:

Backend validates credentials and sends:

{
  "accessToken": "jwt_token",
  "refreshToken": "refresh_token"

2. JWT Token

JWT (JSON Web Token) is used for authentication.

It contains:

- user info
- expiry time
- signature

Example:

eyJhbGciOiJIUzI1NiIsInR5cCI...

Usually:

Access token → short expiry (15 mins)
Refresh token → long expiry (7 days)

3. Store Token

Usually:

Token	                                     Storage
Access Token	              =>             sessionStorage / memory
Refresh Token	HttpOnly      =>             cookie (most secure)

Frontend stores token after login:

localStorage.setItem('token', response.accessToken);

Interview Point:

localStorage is vulnerable to XSS attacks
- HttpOnly cookie is more secure because JS cannot access it

4. Interceptor

Interceptor automatically attaches token in every API request.

Without interceptor:

headers: {
 Authorization: Bearer token
}

in every API manually.

Interceptor avoids repetition.

- Angular Interceptor Flow => Request → Interceptor → Add JWT Token → API Call

Example:

intercept(req: HttpRequest<any>, next: HttpHandler) {

  const token = localStorage.getItem('token');

  if (token) {
    req = req.clone({
      setHeaders: {
        Authorization: `Bearer ${token}`
      }
    });
  }

  return next.handle(req);
}

5. Route Guard

Guard protects routes.

Example:

- Without login → cannot access dashboard
- After login → allow access

Example:

canActivate(): boolean {

  const token = localStorage.getItem('token');
 
  return !!token;  #the !! converts the value into a boolean:
  
}

If a token exists, allow navigation; otherwise, block navigation.

Auth Service
@Injectable({
  providedIn: 'root'
})
export class AuthService {

  private accessToken: string | null = null;

  constructor(
    private http: HttpClient,
    private router: Router
  ) {}

  login(credentials: any) {

    return this.http.post<any>(
      'https://api.example.com/login',
      credentials,
      {
        withCredentials: true
      }
    ).pipe(
      tap(response => {

        // Store access token
        this.accessToken = response.accessToken;

        // Refresh token is stored by backend
        // as HttpOnly cookie.
      })
    );
  }

  getAccessToken(): string | null {
    return this.accessToken;
  }

  refreshToken() {

    return this.http.post<any>(
      'https://api.example.com/refresh',
      {},
      {
        withCredentials: true
      }
    ).pipe(
      tap(response => {

        this.accessToken = response.accessToken;

      })
    );
  }

  logout() {

    this.http.post(
      'https://api.example.com/logout',
      {},
      {
        withCredentials: true
      }
    ).subscribe({
      next: () => {
        this.accessToken = null;
        this.router.navigate(['/login']);
      },
      error: () => {
        this.accessToken = null;
        this.router.navigate(['/login']);
      }
    });
  }
}

8. HTTP Interceptor
Now every protected API request needs:

Authorization: Bearer <accessToken>
Instead of manually doing this:

this.http.get(url, {
  headers: {
    Authorization: `Bearer ${token}`
  }
});
we use an interceptor.

Interceptor
@Injectable()
export class AuthInterceptor implements HttpInterceptor {

  constructor(
    private authService: AuthService
  ) {}

  intercept(
    req: HttpRequest<any>,
    next: HttpHandler
  ): Observable<HttpEvent<any>> {

    const token = this.authService.getAccessToken();

    if (token) {

      req = req.clone({
        setHeaders: {
          Authorization: `Bearer ${token}`
        }
      });

    }

    return next.handle(req);
  }
}

13. Interceptor With Refresh Token
A simplified version:

intercept(
  req: HttpRequest<any>,
  next: HttpHandler
): Observable<HttpEvent<any>> {

  const token = this.authService.getAccessToken();

  if (token) {

    req = req.clone({
      setHeaders: {
        Authorization: `Bearer ${token}`
      }
    });

  }

  return next.handle(req).pipe(

    catchError((error: HttpErrorResponse) => {

      if (error.status === 401) {

        return this.authService.refreshToken().pipe(

          switchMap(() => {

            const newToken =
              this.authService.getAccessToken();

            const clonedRequest = req.clone({
              setHeaders: {
                Authorization: `Bearer ${newToken}`
              }
            });

            return next.handle(clonedRequest);

          }),

          catchError(refreshError => {

            this.authService.logout();

            return throwError(() => refreshError);

          })

        );

      }

      return throwError(() => error);

    })

  );
}
This demonstrates the basic concept.

But don't use this exact version blindly in production because there are two important problems we need to solve.

16. BehaviorSubject Approach
Important variables:

private isRefreshing = false;

private refreshTokenSubject =
  new BehaviorSubject<string | null>(null);
When refresh starts:

this.isRefreshing = true;

this.authService.refreshToken().subscribe({
  next: (response) => {

    this.isRefreshing = false;

    this.refreshTokenSubject.next(
      response.accessToken
    );

  }
});
Other requests wait:

return this.refreshTokenSubject.pipe(

  filter(token => token !== null),

  take(1),

  switchMap(token => {

    const clonedRequest = req.clone({
      setHeaders: {
        Authorization: `Bearer ${token}`
      }
    });

    return next.handle(clonedRequest);

  })

);
Interview explanation
"If multiple requests receive 401 at the same time, I don't want every request to call the refresh API. I use a refresh flag with a BehaviorSubject or shared observable so only one refresh request is made and other failed requests wait for the new access token and then retry."

That's a strong interview answer.

24. Interview Questions You Should Prepare
Q: Why use an access token?
To authenticate API requests without sending username/password repeatedly.

Q: Why short-lived access token?
If the token is stolen, its usable lifetime is limited.

Q: Why refresh token?
To obtain a new access token without forcing the user to log in again.

Q: Where should refresh token be stored?
Preferably in a Secure, HttpOnly cookie, depending on the application's architecture.

Q: Can Angular read an HttpOnly cookie?
No. JavaScript cannot access HttpOnly cookies.

Q: Then how does refresh work?
The browser automatically sends the cookie when Angular calls the refresh endpoint with the appropriate credentials configuration.

Q: What does interceptor do?
It centrally adds the access token to API requests and can handle authentication-related responses such as 401.

Q: What does route guard do?
It controls client-side navigation to protected routes.

Q: Is route guard enough for security?
No. Backend authorization is always required.

Q: What happens when access token expires?
API returns 401, interceptor calls refresh endpoint, backend validates refresh token, a new access token is returned, and the failed request is retried.

Q: What happens when refresh token expires?
Refresh fails, authentication state is cleared, and the user is redirected to login.

Q: What if 10 requests return 401 simultaneously?
Use a shared refresh mechanism such as a refresh flag plus BehaviorSubject/shared observable so only one refresh request runs and the other requests wait for the new token.

Q: What if refresh API itself returns 401?
Don't run refresh logic for the refresh endpoint. Treat the refresh failure as session expiration and log the user out.

  // Validate username/password...

  const accessToken = generateAccessToken(user);
  const refreshToken = generateRefreshToken(user);

  res.cookie('refreshToken', refreshToken, {
    httpOnly: true,
    secure: true,
    sameSite: 'strict'
  });

  res.json({
    accessToken: accessToken
  });
});

Cookies
└── refreshToken = abc123

Angular doesn't need to do:

localStorage.setItem('refreshToken', ...)

and shouldn't do:

document.cookie = `refreshToken=${token}`;

for an HttpOnly refresh token.

Then later, when access token expires

Angular calls:

refreshToken() {
  return this.http.post<any>(

Cookie: refreshToken=abc123

So remember this distinction
                 WHO DOES WHAT?

Backend ────────→ Creates refresh token
Backend ────────→ Sets it as HttpOnly cookie

Browser ────────→ Stores the cookie
Browser ────────→ Sends cookie automatically

Angular ────────→ Uses withCredentials: true
Angular ────────→ NEVER reads HttpOnly refresh token

* If the interviewer asks "Show me the Angular code that stores the refresh token in an HttpOnly cookie," the correct answer is:

"There isn't Angular code that stores it. The backend sets the HttpOnly cookie, and the browser stores it. Angular only uses withCredentials: true so the browser can send the cookie when calling the refresh API."

A route guard protects client-side routes, but the actual security and authorization must always be handled by the backend.

When the access token expires, the API returns a 401 response. The interceptor catches it and calls the refresh endpoint. Angular doesn't directly read the HttpOnly refresh token; the browser automatically sends the cookie when the request is made with the appropriate credentials. The backend validates the refresh token and returns a new access token, after which the interceptor retries the original request.

If the refresh token is expired or invalid, the refresh fails, so we clear the authentication state and redirect the user to the login page. In production, we also handle multiple simultaneous 401 responses so that only one refresh request is made and the other requests wait for the new token."
